# 踩坑与规避清单（玻璃 + WebView + 输入法 + 对齐 + 降级）

> 每条格式：**现象 → 原因 → 规避**。带 ★ 的是本项目实际踩到/改过的。

---

## 一、玻璃效果类（Haze 为主，通用结论兼容其它库）

| # | 现象 | 原因 | 规避 |
|---|---|---|---|
| 1 | 加了 `hazeEffect` 但**完全不模糊** | 少了 `hazeSource`；或两者没共用同一个 `HazeState` | 两个 modifier 都写，共用 `rememberHazeState()` |
| 2 | 同上，但 `hazeSource` 也写了 | ★ Haze 2.x 把实现拆到 **`haze-blur` 模块**，只依赖 `haze` 会静默无效 | 依赖里同时加 `haze` 与 `haze-blur` |
| 3 | 同上，依赖也对 | Haze 2.x **必须显式写 `blurEffect { }` 块**，只写 modifier 不写块 = 没效果 | `hazeEffect(state){ blurEffect { blurRadius = 24.dp } }` |
| 4 | 模糊区变成一块纯色/一块白 | 玻璃容器**有实心底色**（`containerColor` / `background`）把模糊盖住了 | 容器透明；底色交给 tint / 半透明 brush |
| 5 | 画面闪烁、递归绘制、甚至崩 | `hazeSource` 与 `hazeEffect` 是**父子关系** | 改成兄弟节点：`Box { 源(); 玻璃() }` |
| 6 | 列表里滚动时玻璃错位 | 同一 state 被多个 item 复用、`zIndex` 不对 | `hazeSource(state, zIndex = …)`，滚动容器的 source 挂到 item 上 |
| 7 | 弹窗里 tint 变成整屏灰罩 | Dialog 自带 scrim，再叠 tint 就重了 | 用半透明 `Surface` 颜色，别再加 tint |
| 8 | 照抄老教程编不过 | 1.x → 2.x：import 路径改为 `dev.chrisbanes.haze.blur.*`；`rememberHazeState(blurEnabled=…)` 这类参数被移除 | 按当前版本文档写，注意区分 1.x/2.x |
| 9 | 内存泄漏 | `remember { HazeState() }` 被长生命周期对象持有 | 用 `rememberHazeState()` |
| 10 | 帧率明显下降 | 实时模糊本身贵：官方 macrobenchmark 简单页 +29%、图片列表 +45%、复杂拖拽 +98% | 半径调小；`HazeInputScale` 降采样；用 mask 代替 progressive；不可见时 `blurEnabled = false` |
| 11 | 低版本"完全没有玻璃"，只剩半透明 | Haze 在 **Android ≤11 默认不模糊**（只给 scrim）；12/12L 也有折衷 | 这是设计而非 Bug：接受 scrim，或换成 Cloudy（CPU 回退） |
| 12 | WebView / 视频 / 地图上糊不出来 | 背板是 **SurfaceView / TextureView / 独立 View**，与 Compose 不在同一绘制层 | ★ 把 `hazeSource` 挂在**包裹 WebView 的容器**上；仍不行就退回"半透明纯色 + 描边" |
| 13 | 玻璃看起来"像塑料片" | 只有模糊，没有描边高光/亮度差异 | 加 0.8dp 渐变描边（上亮下暗）+ 轻微 tint，观感立刻不一样 |
| 14 | 在纯黑/纯色底上"看不出玻璃" | 模糊的输入是"有细节的背景" | ★ 背景给渐变（本项目给的是深蓝→黑垂直渐变），否则用户以为功能没做 |

## 二、WebView / 浏览器类

| # | 现象 | 原因 | 规避 |
|---|---|---|---|
| 15 | ★ 输入网址 / 点链接**不跳转** | `shouldOverrideUrlLoading` 返回 `true` 却没 `loadUrl()`（返回 true = 我接管了） | 想放行就 **return false**；要接管才自己 `loadUrl` 并 return true |
| 16 | 同上，但代码看着没问题 | API 24+ 走的是 `shouldOverrideUrlLoading(view, WebResourceRequest)`，只重写了废弃的 `String` 版本 | **两个重载都重写**，逻辑收口到同一个函数 |
| 17 | 带端口的地址（`example.com:8080`）跳不动 | 被 `scheme:` 正则误判成未知协议 | 判定时先排除"冒号后是纯数字（端口）"的情况 |
| 18 | 裸域名 `yutongxue.cc.cd` 变成"搜索 xxx" | 用 `startsWith("http")` 判断 | 用宽松域名正则 + 严格 IPv4 + CJK 排除；见 `core/UrlResolver.kt`（已 60/60 实测） |
| 19 | 设为默认浏览器后，点链接 App 起来但**页面没变** | 没重写 `onNewIntent()`（`singleTask` 下热启动不会重新 onCreate） | 重写 `onNewIntent` → `setIntent` → 复用同一套 `handleIntent` |
| 20 | 每点一个链接就开一个新实例 | 没设 `android:launchMode="singleTask"` | 加上；配合 19 一起用 |
| 21 | 在系统"默认应用"里**找不到本 App** | Manifest 少了 `BROWSABLE` 或少了某个 scheme | `VIEW + DEFAULT + BROWSABLE`，且 `http`/`https` 两个 `<data>` 都要写 |
| 22 | 检测"是否为默认浏览器"永远 false | Android 11+ **包可见性**限制，`resolveActivity()` 恒 null | 声明 `<queries><intent>…VIEW http/https…</intent></queries>` |
| 23 | http 站点打不开 | 没有明文流量许可 | 浏览器必须 `android:usesCleartextTraffic="true"`（或 networkSecurityConfig 精确放行） |
| 24 | 键盘弹出把地址栏顶出屏幕 | 用了 `adjustPan` | `android:windowSoftInputMode="adjustResize"` |
| 25 | favicon 显示"裂图"小方块 | 站点无 `link[rel=icon]` 或 favicon 404，`AsyncImage` 没有 error 兜底 | `placeholder` + `error` + `fallback` 全设成内置地球图标 |
| 26 | 页面白屏 | 只开了 `javaScriptEnabled`，没开 `domStorageEnabled` | 两个都开；`databaseEnabled` 多数站点不需要，可关 |
| 27 | 返回键直接退出 App | 没接 WebView 的 `canGoBack()` | `BackHandler(enabled = canGoBack) { goBack() }`，回不去了才交给系统 |
| 28 | 子资源失败导致地址栏/进度异常 | `onReceivedError` 没判断 `isForMainFrame` | 只处理主框架错误 |

## 三、输入法（IME）类

| # | 现象 | 原因 | 规避 |
|---|---|---|---|
| 29 | ★ 输入法上的"搜索/前往"键**没反应** | Compose 里没配 `KeyboardOptions(imeAction=…)` 或没写 `KeyboardActions` | `KeyboardOptions(imeAction = ImeAction.Go/Search)` + `KeyboardActions(onGo/onSearch/onDone)` |
| 30 | ★ 回车变成换行，动作键永不触发 | `BasicTextField` 没设 `singleLine = true`（XML 里是漏 `android:singleLine`） | Compose：`singleLine = true`；XML：`singleLine + inputType=textUri` |
| 31 | 有的输入法给了键但没触发 | 只接了 `onSearch`，实际给的是 `Go` 或 `Done` | `onGo` / `onSearch` / `onDone` **三个都接到同一个 submit()** |
| 32 | 想"网址给前往、文本给搜索"但键不变 | 没按内容动态算 `imeAction` | 用 `UrlResolver.looksLikeUrl(text)` 计算 `imeAction`，随输入重组 |
| 33 | 键盘遮住输入框 | edge-to-edge + 手写 padding 冲突 | Manifest 用 `adjustResize`，inset 交给 `TopAppBarDefaults.windowInsets`，别手写 `padding(top=24.dp)` |

## 四、Material 3 对齐类

| # | 现象 | 原因 | 规避 |
|---|---|---|---|
| 34 | 整体比系统设置页"高/低一截" | 忘了状态栏 inset | `enableEdgeToEdge()` + `TopAppBarDefaults.windowInsets`（自动） |
| 35 | 左边距和系统设置页不一致 | 左右 inset 一会 12 一会 20 | 统一 **16dp**（设置页列表项标准值） |
| 36 | 齿轮点不中 | 视觉小 + 热区也小 | 视觉可 24dp，**触摸目标 ≥ 48dp**（`Modifier.size(48.dp)`） |
| 37 | 顶栏高度和系统不一致 | TopAppBar 默认 64dp | 搜索栏 48dp + 上下各 8dp = 64dp，正好等于默认高度，`expandedHeight = 64.dp` 明确写出来 |
| 38 | 网页被顶栏挡住 | 没用 Scaffold 的 `innerPadding` | 内容区 `Modifier.padding(innerPadding)` |

## 五、降级 / 性能类

| # | 现象 | 原因 | 规避 |
|---|---|---|---|
| 39 | Android 11 及以下没模糊 → 用户以为坏了 | 实时模糊依赖 `RenderEffect`（API 31+） | 显式三档：Full / Reduced / **Scrim（半透明纯色）**，并在设置页显示"当前档位 + 判定理由" |
| 40 | 低内存设备上卡顿 / OOM | 每帧截屏 + 离屏 bitmap | Scrim 档**零离屏分配**；判定用 `ActivityManager.isLowRamDevice`（Android 官方内存能力信号） |
| 41 | 开了 RenderScript blur 反而更卡 | RenderScript 方案是"后台线程处理、内容滞后一帧、一帧只处理一张" | 别开；用 Scrim 档替代（Cloudy 的 C++ 回退也要评估发热） |
| 42 | 大面积玻璃掉帧 | 模糊区域越大越贵 | 只给工具栏/底栏这类小区域上玻璃；滚动列表不用 |
| 43 | 降级后 UI 对比度不够、文字看不清 | Scrim 档底色太透 | Scrim 档把 tint 的 alpha 提到 0.42 左右，并保留描边 |

## 六、选型/依赖类（来自本次 7 库调研）

| # | 现象 | 原因 | 规避 |
|---|---|---|---|
| 44 | 照抄某个 GitHub 库的坐标，Gradle 拉不到 | 该库**没有发布到 Maven/JitPack**，只能在仓库里 `implementation(project(":glass"))` 或自己发 | 选型时先查 Maven Central / JitPack 的 `maven-metadata.xml`，能查到版本号才算可用 |
| 45 | 按别人给的库名去 GitHub 搜不到 | 名字可能是口口相传时走样的（本次 7 个名字里有 1 个检索不到） | 以坐标 + 仓库页为准，找不到就换等价物，别硬等 |
| 46 | 库在 Android 13 以下"什么都不画" | 有些液态玻璃库低版本是"保持透明、不渲染"（不是降级，是消失） | 自己补一层兜底底色；或换有真降级分档的库 |
| 47 | alpha 库升级后编译失败 | API 处于漂移期 | 能锁版本就锁；把库调用**收口到自己的一个 modifier/封装里**（本项目就是 `glassSurface`），换库只改一个文件 |
