# 液态玻璃（Liquid Glass / Glassmorphism）库评估与选型

> 评估时间：2026-10-13 · 数据来源：GitHub 仓库页、Maven Central / Sonatype 实际元数据、各库官方文档站
> 评估方法：能拿到 Maven 元数据的**逐个查了版本号**，拿不到的直接标注"未发布/需 vendor"，不猜测。

---

## 一、结论先行

| 决策 | 内容 |
|---|---|
| **推荐** | **chrisbanes/Haze 2.0.1**（`dev.chrisbanes.haze:haze` + `haze-blur`）作为本项目唯一玻璃实现 |
| **理由（一句话）** | 唯一同时满足「Compose 原生 / 维护活跃 / 依赖坐标稳定 / 允许我自己控制采样源」的库，而**浏览器场景必须能控制采样源**（背后是 WebView） |
| **备选①** | `io.github.nadeemiqbal:liquid-glass` —— 它内置的 **Full/Medium/Fallback 三档自动降级**跟本项目需求几乎一模一样，如果你不想自己写降级逻辑就选它 |
| **备选②** | `com.github.skydoves:cloudy` —— 想让 **Android 11 及以下也真模糊**（走 native C++ CPU 回退）时选它，代价是内存与发热 |
| **不用** | QmDeve（View 体系 + 低于 13 什么都不画）、Mortd3kay（未发 Maven 要 vendor）、Kyant0（alpha、不能嵌套、大面板风险）、SidZadaun02（**未核实到该仓库**） |

## 二、逐库评估矩阵（7 个指定库 + 补充发现）

### 1) chrisbanes/haze ★ 推荐

| 维度 | 结论 |
|---|---|
| 坐标 / 版本 | `dev.chrisbanes.haze:haze:2.0.1`、`dev.chrisbanes.haze:haze-blur:2.0.1`（Maven Central 元数据实测 latest=2.0.1） |
| 最低 API | 库本身全版本可用；**真模糊需 Android 12+（API 31）**，实际默认只在 **32+** 启用 |
| Compose 集成 | ✅ **纯 Compose / Compose Multiplatform 原生**，无 AndroidView 互操作 |
| 低端机性能 | 官方 macrobenchmark：简单 Scaffold **+29%** 帧耗时、图片列表 **+45%**、复杂拖拽 **+98%**；可 `inputScale` 降采样、`blurRadius` 调小、不可见时关掉 |
| 内置降级 | ✅ 有。Android 11 及以下**默认不模糊**，退化为半透明 scrim；12/12L 有专门 workaround（progressive 仅支持线性渐变，其余降级为 mask） |
| 已知坑 | ① 2.x **必须**显式写 `blurEffect {}`；② 2.x import 路径换成 `dev.chrisbanes.haze.blur.*`；③ `hazeSource` 与 `hazeEffect` 必须共用同一个 state 且**不能父子嵌套**（递归绘制）；④ Dialog 里加 tint 会变成整屏 scrim；⑤ 用 `rememberHazeState()` 而不是 `remember { HazeState() }`（后者泄漏） |
| 文档 | 完整（chrisbanes.github.io/haze），有版本迁移指南与平台能力表 |

### 2) Kyant0/AndroidLiquidGlass

| 维度 | 结论 |
|---|---|
| 坐标 / 版本 | JitPack / 源码引入；**alpha 阶段**，README 原话"every API may be changed" |
| 最低 API | **Android 13（API 33）+** |
| Compose 集成 | ✅ Compose 原生（`Modifier.drawBackdrop` / `rememberLayerBackdrop`），1.0.0-alpha09 起换成 Backdrop API |
| 低端机性能 | 折射在 GPU 上算，**小控件**（按钮/图标）没问题；整条工具栏这种大面积**未经验证** |
| 内置降级 | ⚠️ 无明确降级层，需自己判断 `Build.VERSION.SDK_INT` |
| 已知坑 | ① **同类 provider 不能嵌套**：`LiquidGlassProvider(state){ LiquidGlass(state){} }` 不支持，必须改成兄弟节点；② 库**不提供任何现成组件**（LiquidButton 等都是示例代码，要自己抄）；③ 旧教程的 `liquid-glass` 模块已 deprecated |
| 适用 | 想要 iOS 26 那种"折射+色散"质感的**小控件点缀** |

### 3) skydoves/Cloudy

| 维度 | 结论 |
|---|---|
| 坐标 / 版本 | `com.github.skydoves:cloudy`；Maven 元数据实测 latest=**1.0.0-alpha01**（0.7.1 为稳定线末端，老文档里的 0.5.0 已过时） |
| 最低 API | **Android 31+ 走 RenderEffect（GPU）**；**Android 30 及以下走 native C++（NEON/SIMD）CPU 回退**；API 21+ 可跑 |
| Compose 集成 | ✅ Compose Multiplatform 原生（`Modifier.cloudy()`；1.x 还有 `Modifier.cloudy(sky=…)` 背板模糊、`Modifier.liquidGlass()`、`Mirage`） |
| 低端机性能 | CPU 回退能出图，但**逐帧截屏+CPU 模糊**，整屏大面积会明显掉帧、耗内存 |
| 内置降级 | ✅ 有，且可观测：`CloudyState.Success.Applied`（GPU）/ `Success.Captured`（CPU 出图）/ `Success.Scrim`（背板模糊在 ≤30 只给遮罩）/ `Error` |
| 已知坑 | ① CPU 回退是"异步出一张 bitmap"，滚动时容易滞后；② 列表里用要共享 `rememberGraphicsLayer()`；③ 1.0.0-alpha 的 API 与 0.x 有差异，照抄旧博客会编不过 |
| 适用 | 需要 **Android 11 及以下也真模糊**、且能接受 CPU 开销 |

### 4) NadeemIqbal/liquid-glass ★ 降级需求最贴合

| 维度 | 结论 |
|---|---|
| 坐标 / 版本 | `io.github.nadeemiqbal:liquid-glass`；README 写 0.2.3，Maven Central 上可见 0.1.0（作者在 dev.to 发布时是 0.1.0） |
| 最低 API | Full 档：**Android 12+ 且非低内存**；低于此自动进 Fallback |
| Compose 集成 | ✅ Compose Multiplatform 原生：`Modifier.liquidGlass()` + `GlassCard` / `GlassButton` / `GlassNavBar` |
| 低端机性能 | **设计目标就是"不在 2GB 设备上 OOM"**：Fallback 档**零离屏分配**、跳过模糊 |
| 内置降级 | ✅✅ **三档显式分档 + 自动判定**，这是它最大的卖点：<br>Full 24dp/1.4×/全分辨率 · Medium 16dp/1.2×/0.5 降采样 · Fallback 0dp/零分配<br>判定信号：`Build.VERSION.SDK_INT >= 31` + `ActivityManager.isLowRamDevice` |
| 已知坑 | ① 库很新（0.0.x→0.2.x），API 还会动；② 组件数量少（暂无 GlassDialog/GlassBottomSheet 的 M3 封装）；③ 作者自己都说"要更成熟更灵活就用 haze" |
| 适用 | 想**开箱即得分档降级**、不想自己写 `Build.VERSION` 分支 |

### 5) QmDeve/AndroidLiquidGlassView

| 维度 | 结论 |
|---|---|
| 坐标 / 版本 | `com.qmdeve.liquidglass:core`（README 1.1.0；Maven 收录 1.0.5） |
| 最低 API | **Android 13（API 33）+ 才有全效果**；**低于 13 时"保持透明背景、不渲染任何效果"** |

## 三、为什么最终选 Haze

四个硬条件，只有一个库全满足：

| 条件 | 说明 | Haze | Cloudy | liquid-glass | QmDeve | Mortd3kay | Kyant0 |
|---|---|---|---|---|---|---|---|
| Compose 原生（不用 AndroidView 互操作） | 本项目 100% Compose | ✅ | ✅ | ✅ | ❌ | ✅ | ✅ |
| 稳定依赖坐标（Maven Central） | 不用 vendor 源码 | ✅ | ✅ | ✅ | ✅ | ❌ | ⚠️ JitPack |
| **可控采样源**（背板必须是 WebView） | 浏览器场景决定性条件 | ✅ `hazeSource` 可挂任意节点 | ⚠️ 自有模型 | ⚠️ 自有模型 | ❌ | ⚠️ | ✅ |
| 维护活跃 + 文档完整 | 长期可用 | ✅ | ✅ | ⚠️ 新 | ✅ | ⚠️ 实验 | ⚠️ alpha |

**决定性的一条是"可控采样源"**：本项目的玻璃背后是 **WebView**（一个独立 View、有自己的绘制图层），
"什么时候采样、采哪块区域"必须由我们决定。Haze 的 `hazeSource` + `HazeState` 正好提供这个控制点；
而 `GlassCard` / `LiquidGlassView` 这类"自成一体"的组件把采样封装死了，遇到 WebView 这种异类背板就很难调。

另外 Haze 的降级是"自动 scrim"，我们在这之上再加一层自己的三档（见下），
这样**低端机上的行为完全可控**，而不是寄希望于某个库的内部判断。

## 四、集成代码（Haze 2.0.1，含三档降级）

### 4.1 依赖

```toml
# gradle/libs.versions.toml
[versions]
haze = "2.0.1"
[libraries]
haze      = { module = "dev.chrisbanes.haze:haze",      version.ref = "haze" }
haze-blur = { module = "dev.chrisbanes.haze:haze-blur", version.ref = "haze" }
```
```kotlin
// app/build.gradle.kts
implementation(libs.haze)
implementation(libs.haze.blur)      // ← 2.x 少了这行 = 完全不模糊（最常见的坑）
```

### 4.2 抽象成一个 modifier：三档自动降级

见 `app/src/main/java/com/glassbrowser/glass/GlassSurface.kt`，核心：

```kotlin
fun Modifier.glassSurface(tier: GlassTier, hazeState: HazeState, shape: Shape): Modifier = this
    .clip(shape)
    .then(
        if (tier.supportsRealTimeBlur)
            Modifier.hazeEffect(state = hazeState) {
                blurEffect {                                  // 2.x 必须显式写
                    blurRadius = if (tier == GlassTier.Full) 24.dp else 12.dp
                }
            }
        else Modifier                                          // Scrim 档：不挂任何模糊，零离屏分配
    )
    .background(tintFor(tier))                                 // 降级档用更实的半透明纯色
    .border(0.8.dp, glassEdgeBrush(), shape)                   // 顶部高光描边：玻璃感的一半
```

### 4.3 采样源与玻璃的接线（浏览器特有）

```kotlin
val hazeState = rememberHazeState()

Box {
    // 采样源：全屏背景层
    Box(Modifier.fillMaxSize().background(appGradient).hazeSource(hazeState))

    Scaffold(
        containerColor = Color.Transparent,     // ★ 不透明就没有玻璃
        topBar = { /* 内部用 glassSurface(...) 的搜索栏 */ },
    ) { inner ->
        BrowserWebView(modifier = Modifier.fillMaxSize().padding(inner))   // 网页不被遮挡
    }
}
```

## 五、降级判断逻辑（说明 + 依据）

```kotlin
fun detect(context: Context, forced: GlassTier? = null): GlassTier {
    if (forced != null) return forced                       // 设置页可强制覆盖
    val sdk = Build.VERSION.SDK_INT
    val lowRam = context.getSystemService(ActivityManager::class.java)?.isLowRamDevice == true
    return when {
        sdk >= 33 && !lowRam -> Full                        // Android 13+，最佳环境
        sdk >= 31 && !lowRam -> Reduced                     // Android 12/12L，可用但有折衷
        else -> Scrim                                       // ≤11 或低内存：不模糊，只半透明
    }
}
```

| 档 | 触发条件 | 行为 | 依据 |
|---|---|---|---|
| Full | API 33+ 且非低内存 | 24dp 实时模糊 | Haze 官方平台表：**33+ 是"optimal environment"**；AGSL 也从 33 起可用 |
| Reduced | API 31–32 或低内存 | 12dp 实时模糊 | Haze 官方：12/12L 需要 workaround（progressive 仅线性渐变），**默认只在 32+ 启用模糊**，风险更高 |
| Scrim | API ≤30 或低内存强制降 | **完全不做模糊**，半透明纯色 + 描边 | Haze 官方：**≤30 默认不模糊**（RenderScript 方案"慢、滞后一帧、实验性"）；`isLowRamDevice` 是 Android 官方给的内存能力信号 |

两个刻意的设计选择：

1. **不启用 Haze 的 RenderScript 模糊**（`blurEnabled = true`）——官方自己说它"实验性、处理一帧可能超出帧预算、内容滞后"，浏览器这种持续滚动的场景不适合；
2. **Scrim 档零分配** —— 不建离屏 bitmap、不挂 `hazeEffect`，在 2GB 设备上不会 OOM，也不会因为每帧截屏掉帧。
